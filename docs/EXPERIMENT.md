# 实验权限与对比规则
cupsize-v1，实施前冻结。已有优惠券是基线；本次新增杯型/改配。原企业项目、Codex准备、WorkBuddy执行分别陈述。

## 操作范围
允许在指定独立项目副本内读代码、安装锁定npm依赖和Chromium/WebKit、启动本机服务、修改业务/必要测试及局部配置、执行测试修复、保存日志截图视频、构建dist并本地验证。下载依赖/浏览器可联网；应用业务须无外部请求。
优先兼容的已安装Node；没有时报告安装方案，不自动覆盖系统环境。不得sudo、修改全局缓存权限、删除共享缓存、终止他人进程、公网发布、真实支付/下单或读无关私密文件。仅停止本次所属服务。
必要依赖/配置变更记原因及锁文件差异；不能改冻结验收、减覆盖或虚构报告。

## A/B条件
两组各从同一coffee-cupsize-baseline.zip解压到空目录，使用新会话。包不含skills/四阶段说明、实现答案、依赖、dist、旧日志或.git。
相同需求、验收、测试范围、旧tests、脚本、工具权限、模型/推理设置、环境初始条件。唯一预定差别：B使用四Skill交接/修复流程，A收到普通共同任务提示。A自行测试允许，不能禁止测试或故意弱化提示。
A在安装技能前跑，或确实禁用/移除四技能后新开会话；避免自动调用污染。无法隔离要说明，不能作严格因果结论。四Skill不自动等于四个独立/并行Agent，实际角色执行方式照实记录。

## 双组共同任务提示
“请在这个山隅咖啡项目完成docs/FEATURE-SPEC.md的杯型选择与购物袋改配需求，保留优惠券、页面风格和旧数据。验收以docs/ACCEPTANCE.md和docs/E2E-PLAN.md为准，权限见docs/EXPERIMENT.md。完成实现、验证和本地静态交付，记录真实命令结果、失败及人工介入，不能修改冻结标准。先运行npm run check:contract并记录工具、模型、时间和环境。”

## 统一预算与记录
预先每组总上限60分钟，从开始执行至停止，含安装/下载/测试；连续3轮修复无实质进展则停。各1次首轮；若重复，双方同次数且汇总所有结果。可在任一组开始前统一调整预算并更新合同，不能见结果后单方加时。
记录工具/模型/设置、系统/Node/npm/浏览器版本、开始结束、安装和功能耗时、人工介入次数、首次自报完成、首次完整验收、A01–A12最终状态、自然失败及修复轮次。保留系统Node，项目npm/浏览器缓存从空开始，不宣称全新电脑。
普通组停止后若没独立验收，保留成品快照再按相同标准只读评分，不替它修复。新测试可能不同，比较冻结验收及同等外部检查，不只比较各自自写测试通过率。
网络安装失败和业务错误分开；超时/未验证不算通过。不植入bug、替换预制答案或挑成功点；一次实验不能推导“有Skill必然正确”或企业节省金额。
