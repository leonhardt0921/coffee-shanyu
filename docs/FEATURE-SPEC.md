# 待实现：杯型选择与购物袋改配
合同cupsize-v1，2026-10-23。供WorkBuddy实测；本需求尚未实现。

## 已有基线
山隅咖啡是原创概念H5，React + TypeScript + Vite；首页、六款商品、本地购物袋、四页导航。菜单/订单/我的为展示页。已有满39减10开业券：领取后默认启用，每次试算最多减10元，可取消使用；购物袋及券状态刷新保留。所有数据/图片本地，无后台、支付或真实订单。
商品标准价（整数分）：americano1900、latte2200、oat2600、flat-white2400、cold-brew2500、vanilla2800。不得改价迎合测试。

## 新增需求
1. 六款商品加购先选标准杯/大杯，默认标准杯；大杯在原价上加300分。展示所选单价，确认才加入一杯；取消/关闭/Escape不加购。
2. 购物袋展示商品、杯型、单价、数量、行金额。商品ID+杯型为行身份：同款同杯型合并，同款不同杯型分行；总件数为杯数总和。
3. 每行可改杯型，编辑整行、默认当前杯型。确认保留原数量并重新计算；取消不变。改成已有杯型时合并数量，只留目标一行，不能丢杯或重复计价。
4. 每行数量1至99整数；减至0删除；保留删除/清空。加购/增加不得超过99；合并超过99时明确提示，整次编辑不生效，原两行及金额保持，不静默丢弃数量。
5. 所有金额用整数分并显示两位小数。旧券按改配后的商品小计判断：已领且启用且>=3900分减1000分，否则不减；7800分也只减1000分。原取消使用、再次达标恢复、清空等规则不变。
6. 刷新保留杯型、数量及券状态。旧localStorage shanyu-cart-v1商品ID→数量对象迁移为标准杯；旧shanyu-coupon-v1合法状态保留。可改内部模型/键名，但不能丢合法旧商品、重复导入或清空后旧数据复活。使用新键时明确版本优先级，不导入过期旧数据。
7. 保存/迁移失败显示提示，不破坏原持久数据和已提交状态，恢复后可重试，不显示假成功。非法JSON安全恢复为空；混合有效/无效行保留有效行，拒绝未知商品/杯型、负数、小数、>99等非法数量，不能崩溃或出现NaN/负金额。
8. 保持当前视觉。320/375/390/430px和桌面可用；触控目标至少44×44px；长列表和弹窗可滚动，底栏不遮挡；焦点约束、Escape关闭、关闭后回到合理触发控件；支持reduced-motion。
9. 全部本地Mock/资源；不新增登录、后端、支付、真实订单、库存或公网发布。故障注入仅在测试中，生产代码不埋故障开关。

## 固定算例
干净浏览器先领取并启用已有券：
标准拿铁22 + 大杯拿铁25 = 两行两杯，小计47、优惠10、合计37。
把标准杯整行改大杯 = 大杯拿铁一行2杯，小计50、合计40。
减至1杯 = 25、优惠0。刷新仍大杯1杯25。
编辑改选标准杯后取消 = 仍大杯1杯25。
独立旧数据用例：旧美式1+拿铁1迁移成两个标准杯，小计41，券启用时31。
