# WorkBuddy 独立复验说明

本项目区分基础包和完成参考版。请把基础包解压到新的空目录；不要使用已装依赖或已加优惠券的参考版作为首次执行证据。原始企业方案、Codex 本次执行、WorkBuddy 后续复验是三组不同事实。

四个技能各自是一个含 SKILL.md 的目录，位于 skills/。可在工具的技能管理界面按其当前支持方式导入；也可让对应角色明确读取项目中该 SKILL.md。不要假定不同工具会自动识别本项目 skills/ 目录。

## 建议按顺序发送的任务

1. 环境配置：「请读取并执行 skills/coffee-env-setup/SKILL.md，配置这个基础项目的环境，验证基础页面，保存真实日志与报告。不要提前开发优惠功能。」
2. 开发：「环境验证通过后，请按 skills/coffee-feature-dev/SKILL.md 和 docs/FEATURE-SPEC.md，实现首页开业礼满39减10，保留现有设计与交互，保存开发交接报告。」
3. 自动化测试和修复：「请独立读取 skills/coffee-test-repair/SKILL.md、需求和 E2E 计划，编写并真实执行单元及端到端测试。出现真实失败时保留证据、修复再回归；没有失败则如实报告。」
4. 本地交付：「确认第三角色验收通过，再执行 skills/coffee-local-delivery/SKILL.md，构建 dist 并对本地静态成品重跑端到端测试。只监听127.0.0.1，保存源码版本、构建结果及交付证据。」

四个角色顺序交接，可由产品现有 Agent/任务能力承载。只有实际运行过的角色和测试才计为成功，不把技能文件存在等同于技能验证通过。

## 文章采集

- 运行前：工具名、时间、基础源码版本、依赖是否存在、首页原貌。
- 环境：版本检查、真实安装结果；若失败，原始错误及修复后的成功结果。
- 开发：首页新增活动前后同尺寸截图，变更文件与需求说明。
- 测试：连续录像记录「加购19+22→41、领取→31、取消→41、恢复→31、减购不足门槛、恢复并刷新」；独立浏览器自动化报告与真实失败/修复（如有）。
- 交付：生产构建、dist 服务地址、生产环境 E2E、校验摘要。
- 保留原始素材。文章可剪辑标注过程，但不可伪造日志、真实订单、节省金额或 WorkBuddy 尚未发生的结果。

移动适配报告注明浏览器引擎与模拟视口；真实 iPhone/安卓设备未测时明确说明。无公网部署、无支付和实际交易。
