先读 docs/FEATURE-SPEC.md、docs/E2E-PLAN.md。从需求定义预期，随后检查实现和现有测试。

1. 使用 Vitest 验证整数分边界、开关、重复领取与错误数据；使用 Playwright 在真实浏览器执行完整用户路径，不只断言成功提示。
2. E2E 要隔离浏览器存储，运行手机 Chromium、手机 WebKit 和桌面场景；涵盖未领→领券→加购→达标→取消使用→减购失效→恢复→刷新持久化→清空→辅助页回归。至少一条连续测试贯穿完整流程。
3. 覆盖连点、持久化失败/恢复、畸形存储、弹窗键盘/触控、375/390/430及320宽度无溢出、固定栏不遮挡。截取真实页面；测试注入仅在测试上下文使用。
4. 捕获 pageerror、失败资源和第三方请求，必要请求白名单仅127.0.0.1/localhost。报告失败截图、视频、trace及原始命令结果。不要把有意模拟存储失败说成 Agent 开发失误。
5. 若失败：保留证据→定位根因→最小修复→重跑受影响用例→运行完整回归。最多连续三轮无进展后报告具体阻塞。不能删除/跳过测试、放松断言或盲目更新截图来变绿。
6. 真实记录 tests、通过/失败/跳过、运行环境、源码版本、修复前后结果。全部通过时允许交付；否则不交付为成功。首次全绿如实说，不制造失败故事。

本角色可修复发现的项目缺陷；基础截图只是排版参考，不能用一张整页图片替代应用。运行 npm run test:unit、npm run test:e2e。交付角色另在生产构建运行 npm run test:e2e:prod。
