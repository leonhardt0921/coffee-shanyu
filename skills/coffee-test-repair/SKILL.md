# 独立 E2E 验收及修复闭环

使用用户指定项目根目录。先读docs/FEATURE-SPEC.md、docs/ACCEPTANCE.md、docs/E2E-PLAN.md、docs/EXPERIMENT.md及环境/开发报告；先从冻结规则列用例和预期，之后再检查实现。运行npm run check:contract。前置缺失不得报告已验收。

1. 建立A01–A12→单测/E2E/证据矩阵。原tests只是旧功能回归；必须新增杯型测试，不能只跑旧测试后宣布成功。实现尚未支持时测试应真实失败，不为了全绿回填已有答案。
2. 使用真实Playwright浏览器，不以组件快照/HTTP200替代。主流程一条连续测试：领券→标准拿铁22→大杯25→两行47/37→标准改大杯合并一行2杯50/40→减为1杯25→刷新25→改选标准后取消仍25。逐步断言行身份、杯型、数量、单价、小计、优惠和合计；主流程不靠直接写存储造结果。
3. 完整覆盖E2E-PLAN：旧优惠券旅程、旧存储迁移及重复刷新/清空不复活、保存/迁移失败和恢复、坏数据、数量99与合并超限、连点、原导航/图片/增减删清空。旧数据/故障注入仅在测试上下文，报告明确“主动异常路径”，不能宣传成自然bug。
4. 三项目全跑：手机Chromium、手机WebKit、桌面Chromium；补320/375/430和320×568，验证新弹窗触控/焦点/Escape/滚动/底栏/reduced-motion。捕获未处理异常、HTTP错误、真实资源失败及第三方请求；不要忽略全部错误。使用独立上下文与唯一报告目录。
5. 单测补充整数分/优惠边界、变体/合并/迁移规则。执行npm run typecheck、npm run test:unit、npm run test:e2e，记录真实退出码、总数、通过/失败/跳过；完整运行retries=0。
6. 新交互允许调整旧测试操作步骤和内部接口，但旧业务断言/兼容性覆盖保留；逐项记录理由和diff。不能删/skip/only、放宽预期、改冻结文档或盲目更新图片让它绿。
7. 真实失败按“保留每轮日志/截图/视频/trace→根因→最小修复→定向验证→完整回归”。可修复项目代码或协调开发角色；不得覆盖失败目录。连续3轮无实质进展或共同预算到达则报告未通过/阻塞，不无限循环。首次全绿照实写。
8. 主流程无论成功/失败保留视频和trace，关键步骤截图；其余失败保留视频/trace/截图。记录源码哈希、浏览器版本/视口、验收映射和修复前后结果，写artifacts/<run-id>/testing/testing.md。报告只证明实际执行过的项目；模拟手机不称实体机。
9. 开发环境A01–A11及相关检查通过后交给交付阶段；A12生产部分此时标“待交付验证”，不能提前说全部通过。交付修改代码后须返回完整回归。不得把历史Codex证据当本轮WorkBuddy日志。
