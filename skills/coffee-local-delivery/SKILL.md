# 本地构建、生产验收和交付

项目根目录由用户指定。读取docs/ACCEPTANCE.md、docs/E2E-PLAN.md、docs/EXPERIMENT.md和测试报告。运行npm run check:contract，核对测试所用源码与当前源码一致；缺测试证据或尚有失败不得跳过门禁。

1. 记录本轮源码版本/完整文件哈希、锁文件和测试文件哈希。将旧dist移入本轮备份（若有）后执行npm run build，保存输出与退出码。失败不能交旧产物。
2. 确认新的dist/index.html与本地资源存在。通过npm run test:e2e:prod让Playwright启动独立dist静态服务并运行同套完整E2E；生产服务只监听127.0.0.1，报告目录唯一。不能用Vite开发页面或首页HTTP200代替成品验收。
3. 验证连续杯型改配主流程、旧券/旧数据/异常/导航/移动适配在生产产物也通过；保存JSON/HTML、成功主流程录像/trace、失败证据。出现失败按测试修复闭环回退；源码改后重新完整开发回归→重新build→完整生产回归，不能沿用旧通过报告。
4. 仅全部A01–A12通过且无跳过/未验证，写“本轮通过”。缺浏览器/预算用尽写未完成；不把构建成功或脚本退出0单独当业务成功。
5. 整理源码包（不含node_modules/.workbuddy-cache/artifacts/.git）、dist包、冻结合同、锁文件、运行说明、SHA256及真实报告。源码包是本次已实现杯型的完成版，与输入基线分别命名，不覆盖基线ZIP。
6. 如需用户预览，再npm run serve:dist -- --port <空闲端口>启动独立成品；记录实际URL/PID/源码对应关系及关闭方式。只保留明确交付的预览服务，停止本轮其余服务；不终止其他项目进程。
7. 写artifacts/<run-id>/delivery/delivery.md：时间、命令/退出码、生产测试数量、A01–A12证据映射、人工介入和所有自然失败/修复、产物路径/哈希、未测范围。如实注明这是本地静态交付，非公网部署、实体手机或真实订单验证。
8. 不上传发布、不伪造日志、不将旧Codex结果冒充WorkBuddy验证。达到共同预算或连续3轮无进展时记录阻塞并结束当前轮。
